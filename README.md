# Is Code a Form of Art? Reflections on *The Art of Code*

> Note: All core ideas in this essay are my own personal thoughts. AI was only used to refine wording for better clarity and conciseness.

After watching Dylan Beattie’s talk *The Art of Code*, I start from its central question: **can code be understood as art?** With the development of artificial intelligence, code has increasingly become a viable medium for artistic expression.

Most code we encounter exists purely as a practical tool. It solves business requirements, automates workflows and prioritises reliability and efficiency above everything else. Art‑oriented code works differently. It is not built to deliver commercial value. Its goal is to evoke emotion, entertain audiences and produce unique aesthetic experiences.

In Beattie’s presentation, alongside well‑known generative‑art examples, one idea stuck with me: writing code syntax that reads like rock‑and‑roll lyrics. This playful style demonstrates that code can step outside purely functional constraints. It can become a space for creative, expressive play rather than only solving problems.

Before labelling code as art, we need a working definition of art itself. Katharina Gsöllpointner’s *Art as Aesthetic System* theory argues that artistic meaning does not live only inside the finished object. Instead, meaning emerges from a complete interactive cycle: **production → artwork → reception → feedback**. Art is not a static thing; it is an ongoing social process.

This framework helps us think about the modern practice of *vibe coding*. Vibe coding lowers technical barriers and lets ordinary people turn inner ideas into working code. These projects carry strong personal traces: shaped by the creator’s life experience, interests, doubts and experimental choices. No two vibe‑coding works will ever be identical.

From this perspective: **code counts as art when its primary purpose is self‑expression, not commercial delivery**. When the creator makes work for personal expression without needing to satisfy mass‑market requirements, code operates as an artistic medium.

But this status changes with commercialisation. Once a personal vibe‑coding project is released as a public product, full creative control disappears. Developers must respond to user needs, technical limits and market pressures. At this point code shifts back to being a practical tool and loses its primarily‑artistic character.

In conclusion, code is neither inherently art nor only a tool. Its artistic quality depends on **purpose and development stage**. It is a powerful contemporary medium for self‑expression and for connecting with like‑minded creators.
